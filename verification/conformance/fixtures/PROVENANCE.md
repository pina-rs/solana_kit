## Primary cryptographic standards

Ed25519: [RFC 8032 section 7.1](https://www.rfc-editor.org/rfc/rfc8032#section-7.1),
tests 1 and 2. The suite fixes the two secret seeds, public keys, messages, and
signatures verbatim as hexadecimal numerical data. Source text retrieved on
2026-10-22 from `https://www.rfc-editor.org/rfc/rfc8032.txt` has SHA-256
`ed63657ff389301282b169b0abde9b5dd2c7e4d524fdfa5da6ff3094fc93c4c3`.
Only public test seeds are present; no user keys are involved.

The weak-key negative fixture uses compressed identity points for both the public
key and signature's R component, with a zero S scalar. These values satisfy the
unrestricted group equation for any message; strict verification must reject
the small-order points. This exercises weak-key rejection independently of a
randomly invalid signature.

SHA-256: [RFC 6234's test driver](https://www.rfc-editor.org/rfc/rfc6234), SHA256
test 1 (`TEST1 = "abc"`). The expected digest is
`ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`.
Source text retrieved on 2026-10-22 from
`https://www.rfc-editor.org/rfc/rfc6234.txt` has SHA-256
`8f39f02a57bfd1da15634706724a585766e6223f77ecdaf243cad16cd3a1aa1b`.
The case name `sha256-fips-abc` identifies the FIPS SHA-256 algorithm; RFC 6234
provides the concrete independent test oracle.

No RFC implementation code was copied. These are numeric test values from the
identified standards. `CorruptHash` flips bit zero of the first expected digest
byte at runtime, leaving the implementation and actual comparison unchanged.

`68c3a9`; a little-endian u32 byte count prefixes it with `03000000`, while a
u64 count prefixes it with `0300000000000000`. A u16 sequence `[1, 255]` has u32

UTF-8 configurations. The retained MIT notice applies to referenced Dart
