# Rust Solana Kit Codama engine

This production tooling library owns the shared typed frontend and emitter for
native generation and the NPM WASI renderer. It is private and is not a Rust
application dependency or a crate-name reservation candidate.

Build the bundled `solana_kit_codegen_wasi` binary without default features.
Run private proof commands and their complete regression suite with
`--features verification`; existing command arguments remain unchanged.
The historical System output header is retained byte-for-byte as a provenance
identifier, even though its generation source has moved here.

# Shared data generator

This private native tool renders Kit-owned data codecs from pinned Codama inputs.
It shares the typed wire model, shape validation, codec expressions and atomic
single-file writer with the existing instruction generator. It is not a runtime
dependency or a complete Token-2022 client generator.

`token-2022-data <output.rs>` renders the complete pinned data model.
`token-2022-proof <directory>` also writes the ordinary downstream byte-oracle
consumer. The output directory must exist or be creatable by that command.

`alt-config` first validates and renders both complete inputs, then replaces each
output atomically. Its existing output directories must already exist under
`crates/solana_kit_address_lookup_table/src` and `crates/solana_kit_config/src`.
The set is not transactional if a later filesystem replacement fails. These
program clients now belong to the public workspace. Their original immutable
goldens still define the byte comparison.

The two `fixtures/*-generated.rs` files retain the exact accepted ALT and Config
outputs from commit `442316b6b855cdd1eae38d4984d5ef31687628e4`. They are immutable
generator goldens. The drift test compares newly rendered bytes with these
snapshots. Later public program clients must use these same outputs.
`fixtures/alt-config-prior-receipt.tsv` retains the accepted 113-row bounded
private receipt from that commit. It is test input, not the current public parity
ledger or a claim that its named client APIs are available. The receipt audit
command requires the original source cache and installed program notices.

The source fixtures retain their original license notices. The source auditor
retains all 1,829 Token-2022 declaration rows without promoting any to complete.
The 528 Dart rows compare 400 instruction and 12 base-account frames, plus 116
separate bare extension tags and payloads. They are not 528 canonical account
TLV equivalences. Nine original Dart tests are historical source-identical proof.

Tagged variants have contiguous discriminants. Standalone zero remains legal.
TLV account collections reject a zero entry before writing their first extension.
Preflight rejection takes precedence over a later oversized payload. Decoder
termination and spare capacity remain supported. Named structural codecs do not
implement complete program-state validation or reserved-size account dispatch.

`Reader::transaction` is an opt-in cursor and item-budget transaction. Successful
closures commit those two values. Failed closures restore them. External closure
effects remain visible. Ordinary frame and take operations keep their existing
consuming behavior.

All generated code is exclusively for off-chain client applications. Use Pina
or official Solana program libraries for on-chain programs. Validator and installed
desktop, Android and iOS journeys remain separate requirements.

`compression-normalize <output.json>` prepares the complete pinned legacy Anchor
input through the shared typed wire/layout validators and atomically replaces one
normalized artifact. `program-preparation-audit` validates this input and the six
Subscriptions PDA recipes and twenty-eight role defaults. These are preparation
commands, not completed runtime clients. The complete original Subscriptions
input, including seven events, is retained. See the
[preparation notices](fixtures/COMPRESSION-SUBSCRIPTIONS-NOTICE.md) for pins,
licenses, the canonical Compression eight-byte header discrepancy with Dart, and
remaining work.

`compression-generate <output.rs>` projects that complete prepared input through
the shared renderer. Instruction headers retain every literal byte, with duplicate
and prefix ambiguity rejected before output replacement. Existing single-byte
clients retain their exact generated bytes. Native generated consumers exercise
inline and grouped literal dispatch, a 256-variant two-byte domain, a nonzero canonical
Compression ReplaceLeaf invocation and strict proof privileges. Generator tests are
separate from the full public-client matrices and portable runtime receipt.

`subscriptions-generate <output.rs>` lowers the complete pinned Codama account,
event, PDA and default graph through the same typed field/codec/invocation renderer.
The corresponding `solana_kit_account_compression` and `solana_kit_subscriptions`
clients, builders, snapshot helpers and portable registry remain in a separate
unpublished implementation layer.
The explicit instruction budget is 256, independent of named definition limits.
Both complete original inputs and all declaration statuses remain unchanged.

The source checkpoint also registers `squads-generate`, `bubblegum-generate`,
`mpl-core-generate`, `token-metadata-generate` and `attestation-generate`, each
with an explicit output path. Their MIT Dart-derived source models use the same
complete frontend, typed IR, codec emitter and atomic writer. The private primary
audit commands accept external pinned inputs and do not distribute those inputs.
The five new public generated modules remain absent until an admitted generator
run. Their authored public tests, outside consumers and portable registries have
not established compilation or runtime acceptance for this checkpoint.

Complete source models use the existing data validator's 256-definition bound,
including lowered account, event and enum payload records. Legacy linked models
retain their 64-definition bound. Public codec and account decoding limits do
not change. Nested owned strings and counted vectors use conditional private
adapters. Individually length-framed text array elements are admitted; unframed
text array elements still fail validation. New source controls retain exact
presence tags, independent byte literals, item budgets, helper-name collisions
and destination/pending-file preservation. Portable program-client journeys remain
outstanding.
