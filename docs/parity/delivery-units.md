# Remaining implementation units

These units build an off-chain client SDK for applications. Program clients construct
and decode program interactions; they do not make this SDK an on-chain program
library. Use Pina or official Solana program libraries for on-chain code.

Generated from the capability ledger. Each unit has at most 200 exact IDs; the `unit`
column in capabilities.tsv is its authoritative membership, including both range
endpoints below. Units are source-order planning tranches, not promises that a
200-symbol change is one reviewable PR. Split at source/type boundaries during
implementation and retain ID assignments. Source lines count distinct defining
files touched by the tranche, not implementation effort. All units remain pending.

Shared codec composition and a reproducible Kit-owned generator should precede
program tranches. Generated clients share layouts, discriminator rules, builders,
and negative fixtures; do not manually port repeated output before this leverage
is proved. Consult core-codecs.tsv and program-inputs.tsv for their independent
audit results. Mobile units depend on an installed-host bridge, user gestures,
wallet availability, cancellation/unload, emulator and simulator evidence; the
reference platform conditionals do not prove Rust host support.
